## Changed

### Agent SDK upgrade testing should include state and boundary semantics

**Classification:** `changed`  
**Evidence:** official OpenAI Agents SDK repository commits; engineering inference from the concentration of fixes  
**Status:** some reviewed commits were on the main branch and require release verification before being treated as shipped behaviour

Recent fixes touched:

- atomic session mutations;
- preserving guardrail results when a resumed run interrupts again;
- nested conversation-history fidelity;
- tracing and span-scope cleanup during generator closure;
- MCP active-server iteration;
- sandbox patch operation mappings and event handling;
- redaction of JSON validation errors;
- request-ID propagation;
- content-filter refusal propagation.

These changes show that an agent SDK upgrade can alter much more than API syntax. It can affect replay correctness, interruption recovery, auditability, confidential error handling, sandbox integrity, and tool availability.

**Production impact:**

Upgrade gates should test interrupted and resumed executions, concurrent state writes, repeated tool calls, trace completion, malformed model output, content-filter refusals, MCP server enumeration, and sandbox file operations. Do not promote solely because happy-path unit tests pass.

## Engineering pattern of the week

### State-machine upgrade firewall

Treat an agent runtime or SDK upgrade as a change to a distributed state machine and its security boundaries.

```text
Pinned production version
        ↓
Read release and migration evidence
        ↓
Canary environment with captured test corpus
        ↓
State/replay + tool + security regression suite
        ↓
Compare traces, outputs, costs, and failure classes
        ↓
Promote gradually or roll back
```

#### Use it when

- upgrading an agent SDK, orchestration framework, memory provider, sandbox provider, or MCP client;
- changing default models or model settings;
- enabling new persistence, interruption, handoff, or approval behaviour;
- adopting a framework release that spans several packages.

#### Required regression groups

1. **State integrity** — concurrent writes, idempotency, history ordering, checkpoint restoration.
2. **Resume semantics** — approval rejection, interruption, repeated interruption, partial tool completion.
3. **Tool boundaries** — allowed tools, MCP enumeration, duplicate names, malformed tool input, retries.
4. **Sandbox boundaries** — path traversal, symlinks or junctions, patch/move operations, archive extraction, network access.
5. **Observability** — trace closure, request IDs, nested spans, error visibility without sensitive payload leakage.
6. **Model behaviour** — explicit model selection, structured output, refusal handling, cost and latency comparison.

#### Failure modes

- allowing an implicit default-model change to reach production;
- testing only final text output and missing corrupted state;
- assuming patch releases cannot alter operational behaviour;
- relying on unreleased main-branch fixes as if they were available in the installed package;
- logging malformed payloads or validation errors containing confidential content;
- upgrading all framework packages simultaneously without identifying the component that changed behaviour.

#### Trade-offs

This pattern adds release-review and regression cost, but materially reduces silent corruption, security regressions, and difficult rollback scenarios. The depth of testing should scale with tool permissions, data sensitivity, workflow duration, and reversibility.

## Code and repository reading picks

### 1. `microsoft/agent-framework`

**Why it matters:** official Microsoft implementation covering agent abstractions, providers, orchestration, hosting, memory, observability, and Foundry integration.

**Reading order:**

1. root release notes and changelog files;
2. `python/packages/agent-framework-core` for core contracts;
3. provider packages such as Foundry and OpenAI integrations;
4. memory and orchestration packages;
5. hosted-agent and end-to-end samples;
6. tests for approval, memory, workflow state, and tracing.

**Learn:** package maturity boundaries, provider abstraction, workflow state, approval flows, memory scoping, and release coupling.

### 2. `openai/openai-agents-python`

**Why it matters:** official OpenAI agent runtime with active work in sessions, guardrails, tracing, MCP, sandboxes, handoffs, and Responses integration.

**Reading order:**

1. release notes and migration guidance;
2. `src/agents/run.py` and run-state modules;
3. session and memory implementations;
4. tool, guardrail, and MCP modules;
5. tracing processors and span models;
6. sandbox integrations;
7. regression tests associated with interruption, resume, and malformed inputs.

**Learn:** how an agent loop preserves state, how interruptions are resumed, where guardrails execute, and which failure paths require explicit tests.

### 3. `anthropics/anthropic-sdk-python`

**Why it matters:** official Anthropic API client and a useful reference for typed request/response evolution, retries, streaming, and generated-SDK structure.

**Reading order:**

1. changelog and release commits;
2. top-level client and async client;
3. Messages resource implementation;
4. streaming helpers and event types;
5. error and retry handling;
6. tests for beta headers, streaming, and typed payloads.

**Learn:** API-client versioning, transport behaviour, generated type organisation, and how beta capabilities are isolated.

### 4. `MicrosoftLearning/mslearn-ai-agents`

**Why it matters:** official learning exercises aligned with Microsoft agent development concepts and useful for mapping hands-on work to AI-103 objectives.

**Reading order:**

1. repository setup and prerequisites;
2. exercises matching Foundry projects and agents;
3. tool and knowledge integration labs;
4. evaluation, monitoring, and deployment exercises;
5. compare each lab's simplifications with production controls in this playbook.

**Learn:** platform workflow and certification coverage. Treat labs as learning assets, not production reference architectures.
