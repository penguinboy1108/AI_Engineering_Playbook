# AI Engineering Practice Radar — 2026-09-25

## Executive summary

Three mechanisms passed the Signal Gate this week:

1. **Stable-prefix context layout + cache observability.** Persistent agents should keep reusable instructions, tool schemas, and reference context stable, place volatile state later, and monitor cache-hit/miss behavior as an operational efficiency signal.
2. **Evidence-preserving harness compression.** Reduce repeated turns and oversized observations only when original evidence remains recoverable and failed reduction falls back to the source.
3. **Hypothesis fan-out with independent verification.** Parallel agents are useful when search is decomposable and a strong funnel plus independent verifier prevents candidate volume from becoming the success metric.

No certification, lifecycle-table, or routine SDK-version content was promoted.

## Engineering Techniques

### 1. Stable-prefix context layout + cache observability

**Problem.** Long-running agents repeatedly resend system/developer instructions, tool schemas, reference context, and prior state. Small changes near the front of a prompt can invalidate reuse and silently raise latency and cost.

**Technique.** Put stable material first and volatile task state later. Keep tool definitions, schemas, and ordering stable when semantics have not changed. Restrict callable tools without unnecessarily rebuilding the full catalog when the provider supports that. Instrument cache-hit rate, cached/uncached token composition, miss reason, latency, and cost.

**How it works.** Prefix caching reuses computation while the provider considers the prefix reusable. OpenAI's September 22 update adds diagnostics that identify changes to tools, model/settings, or input that caused misses, plus explicit cache breakpoints and prewarming controls.

**Why it works.** It removes repeated inference work without deliberately reducing reasoning or evidence. OpenAI reports that GitHub Copilot reduced the share of prompt tokens requiring fresh processing by more than 50% relative to its prior baseline across billions of requests. Other customer examples report 83%→91% and roughly 85%→90%+ cache-hit improvements with lower inference cost. These are vendor/customer-reported results, not independent benchmarks.

```text
stable policy/instructions
        ↓
stable tools/reference context
        ↓  ← reusable prefix
volatile task state
        ↓
latest observation/input
        ↓
model

telemetry → hit rate + miss reason + latency + cost
```

**Implementation guidance.**
- Version the stable prefix separately from task state.
- Treat tool-schema changes as deployment changes.
- Alert on unexpected cache-hit regressions after prompt/tool releases.
- Benchmark with real multi-turn traces.
- Keep correctness/eval metrics beside cache metrics.

**Trade-offs / failure modes.** Stable ordering can complicate dynamic tool catalogs; appended overrides can create context debt; provider controls are vendor-specific. Do not optimize hit rate by retaining stale context, and never treat a cache hit as evidence of semantic correctness.

**When to use.** Persistent/coding agents, large tool catalogs, shared policy/reference prefixes, background forks, and high-volume multi-turn systems.

**Evidence strength.** Official provider mechanism plus production customer reports.

**Production impact.** Material latency/cost potential without intentionally reducing task work.

**Primary source.** https://openai.com/index/better-prompt-caching-for-gpt-6/

### 2. Evidence-preserving harness compression

**Problem.** Long-running agents spend model turns and context on predictable validation steps, repeated large observations, completed subtasks, and long logs. Naive truncation saves tokens by deleting evidence.

**Technique.** Optimize only behind a recoverability invariant:
- fuse deterministic edit→validate sequences when the follow-up is already known;
- replace repeated large observations with stable handles and exact recall;
- compress eligible logs only while retaining the source;
- compact completed context at explicit progress boundaries;
- make mechanisms independently switchable and measure quality as well as cost.

**How it works.** NVIDIA's SoL-Pi implements Action Fusion, ObservationPack, Evidence-Preserving Reducer, and Online Context Compact as opt-in extensions. Eligible source material is archived locally; reducer failure leaves the original result unchanged; the upstream Pi harness is not patched.

```text
raw evidence
    ↓
eligible?
 ┌──┴──┐
 no   yes
 ↓     ↓
keep  archive source
        ↓
     transform
        ↓
     validate
    ┌───┴───┐
  fail     pass
   ↓         ↓
source   compact view
             ↓
        exact recall
```

**Why it works.** The optimization target is redundant model-visible work, not information destruction.

**Implementation guidance.**
- Define recoverability before compaction.
- Scope archives to run/session and apply retention policy.
- Validate mutable targets before fused follow-up actions.
- Regression-test host integration points.
- Evaluate cost per verified success, not token count alone.
- Treat remote log reduction as a data-egress path.

**Trade-offs / failure modes.** Storage and retrieval complexity increase; compact views can hide weak signals; fused actions can remove decision points; remote reduction can expose sensitive logs; compatibility can drift.

**Evidence strength.** Mature OSS implementation with tests and explicit compatibility/security documentation; research-derived mechanisms.

**Primary sources.**
- https://github.com/NVlabs/SoL-Pi
- https://github.com/NVlabs/SoL-Pi/blob/main/SECURITY.md
- https://github.com/NVlabs/SoL-Pi/blob/main/docs/compatibility.md

### 3. Hypothesis fan-out with independent verification

**Problem.** Agent parallelism can generate enormous candidate volume. Without a funnel and independent verifier, parallelism mostly scales compute and correlated mistakes.

**Technique.** Scale search only when candidates can be progressively filtered by stronger evidence.

```text
many cheap searches/hypotheses
          ↓
evidence-based filters
          ↓
small candidate set
          ↓
expert/independent verifier
          ↓
expensive real-world validation
```

**Evidence.** Anthropic reports a biology workflow using roughly 950 agents for 21 hours and 210 million tokens. The process gathered over 200,000 reverse transcriptases, produced about 3,500 candidate systems, narrowed these to 20 reports, and then used expert review and laboratory experiments as the decisive verifier.

**Engineering lesson.** Define the final verifier before scaling fan-out; track candidate survival at each stage; require evidence artifacts; stop adding parallelism when marginal verified value no longer justifies compute.

**When not to use.** Tightly coupled state, irreversible actions, or tasks where verification is expensive/non-independent.

**Evidence strength.** Production/project evidence in a scientific workflow. The funnel is transferable; the 950-agent scale is not.

**Primary source.** https://www.anthropic.com/news/claude-discovers-novel-enzyme-system

## Repository Deep Dive — NVlabs/SoL-Pi

**Repository:** https://github.com/NVlabs/SoL-Pi  
**Reviewed commit:** `1559b5cb12c72da4a485bc50fe326586b216fb19` (2026-09-22)

### Why study it

SoL-Pi treats token efficiency as a harness-design problem while making evidence preservation, opt-in behavior, compatibility, and security caveats explicit. It also has a substantive test suite rather than only a benchmark/demo.

### Architecture and core abstractions

The project is a standalone Pi extension rather than a fork. Four mechanisms hook into public extension events: Action Fusion, ObservationPack, Evidence-Preserving Reducer, and Online Context Compact. The host remains responsible for authentication, provider/model selection, shell behavior, and the primary agent loop.

### Five high-value areas

1. `src/sol-pi/extensions/action-fusion/` — deterministic follow-up work and race/path handling.
2. `src/sol-pi/extensions/observation-pack/` — archive + stable-handle design.
3. `src/sol-pi/extensions/evidence-preserving-reducer/` — reduction, validation, and fallback.
4. `src/sol-pi/extensions/online-context-compact/` — explicit compaction triggers.
5. `SECURITY.md` + `docs/compatibility.md` — capability, data-egress, and host-version boundaries.

### Engineering treatment

- **State/persistence:** eligible observations are archived under session-specific directories; compaction state stays in Pi's session log.
- **Tools:** Action Fusion wraps edit/write and can invoke a configured validation command.
- **Failure handling:** failed reduction preserves the original result.
- **Evals/tests:** TypeScript checks, tests, package inspection, compatibility checks, and offline startup validation.
- **Security:** the project explicitly says it inherits Pi process permissions and is not a sandbox. Remote reduction is a potential data-egress path.

### Elegant choices

Opt-in optimization; no upstream patch; source evidence retained; conservative fallback; compatibility treated as a tested contract; dedicated tests for path normalization and mutation/validation races.

### Do not copy blindly

Pi-specific APIs, fixed economic thresholds, remote reducers for sensitive logs, or edit→validation fusion when the follow-up is not deterministic and side-effect safe.

## Engineering Pattern of the Week — Recoverable Context Reduction

**Problem.** Context grows faster than decision-relevant information. Blind truncation lowers cost by destroying evidence.

**Mechanism.**

```text
raw observation/completed context
            ↓
      classify eligibility
        ┌───┴────┐
      unsafe    safe
        ↓         ↓
     retain    archive source
                  ↓
              transform
                  ↓
          validate receipt
           ┌──────┴──────┐
         invalid        valid
            ↓             ↓
         original    compact view
                          ↓
                   stable recall key
```

**Invariants.**
1. Source evidence remains recoverable for the workflow's required lifetime.
2. Reduction failure returns original evidence.
3. Compact representations do not gain authority over their sources.
4. Retention/security policy applies to archives too.
5. Quality gates compare verified outcomes before and after reduction.

**Trade-offs.** More storage/retrieval complexity; hidden weak signals; archive privacy obligations; non-obvious interaction with provider caching.

**Evaluation/observability.** Measure verified success, token/cost per verified success, trigger/fallback rate, recall frequency, latency, archive size/retention, and failures attributable to missing context.

**Evidence status.** Observation-layer pattern. Strong OSS implementation evidence plus production evidence that context reuse affects persistent-agent economics. Keep out of canonical guidance until independently validated.
